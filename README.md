# Pour Paint

A target-match pouring puzzle for iOS. Each level shows a **target artwork**: a
tube filled with horizontal color bands. Your supply rack holds tubes of paint —
tap one to pour a band into your canvas tube and replicate the target's band
sequence exactly, within a limited number of pours.

- 50 hand-tuned-feeling levels from a **certified-solvable seeded generator**
  (bands 3→6, colors 3→8, pour slack tightens 3→2→1)
- Star rating: 3★ = match within par pours, 2★ = solved over par,
  1★ = solved with hints or extra pours
- Unlimited undo, restart anytime, "reveal next band" hint
- Juicy SpriteKit presentation: glossy tubes, animated pour streams, splash
  particles, wobble, confetti, synthesized SFX + haptics (no audio assets)
- Native SwiftUI + SpriteKit, iOS 17+, portrait only, fully offline-capable

## Build

Open `PourPaint.xcodeproj` in Xcode 16+ and run on a device/simulator.
To regenerate the project after adding/removing sources:

```sh
python3 tools/gen_pbxproj.py
python3 scripts/generate_icons.py   # only if the icon concept changes
```

## Monetization setup

The whole game is free and fully playable — monetization is optional
helpers (ads + boosters + remove-ads), never a paywall.

### In-app purchases (App Store Connect → create these EXACT products)

| Product ID | Type | Price | Name |
|---|---|---|---|
| `app.pourpaint.game.removeads` | Non-consumable | $4.99 | Remove Ads |
| `app.pourpaint.game.boosters.extrapours10` | Consumable | $0.99 | Extra Pours 10-pack |

- Extra Pours 10-pack grants 10 refills; each refill adds **+2 pours** to the
  current level (persisted count, badge in the HUD, row in Settings).
- StoreKit 2 only: verification + `Transaction.finish()`,
  `Transaction.updates` listener, `AppStore.sync()` restore, refund revocation
  (revoked Remove Ads re-enables ads). No external billing, no web links.

### AdMob checklist

1. Create an AdMob account at apps.admob.com (if needed).
2. Add an **iOS app** for Pour Paint → copy the **App ID**.
3. Create **1 Rewarded** ad unit and **1 Interstitial** ad unit.
4. Paste the IDs into the `// TODO(Henry)` spots in
   `PourPaint/Game/AdsManager.swift` (release branch of the `#if DEBUG`).
5. Replace `GADApplicationIdentifier` in `PourPaint/Info.plist` with the real
   App ID (currently Google's sample test ID — fine for TestFlight testing).
6. Debug builds always use Google's official test IDs — safe to develop with.

Ad behavior: rewarded placements are **+2 pours** and **reveal next band**;
interstitials show at most every 3rd level completion, never mid-level, never
during a new player's first 3 levels, never for Remove-Ads owners. Buying
Remove Ads kills all ads instantly. Everything degrades gracefully offline.

### Banking / tax

Before the first payout: complete the **Paid Applications agreement** and
**banking + U.S. tax forms** in App Store Connect (Agreements, Tax, and
Banking). No payouts happen until these are done.

### Privacy labels

`PrivacyInfo.xcprivacy` declares **Device ID** collected for **third-party
advertising**, not linked to the user, tracking = false (no IDFA, no
AppTrackingTransparency prompt). Mirror this in the App Store Connect privacy
questionnaire: "Device ID — used for third-party advertising — not linked".

## Release

The release pipeline mirrors Henry's other iOS apps:

1. Henry creates the GitHub repo `OverlordLoader/pour-paint` and pushes `main`.
2. Henry uploads `~/workspace/your_files/pourpaint-apple-release.yml` to
   `.github/workflows/apple-release.yml` via the GitHub web UI (subagents
   can't push workflow files — GitHub requires the `workflows` permission).
3. Henry fills the `app-store-release-pourpaint` environment secrets
   (`APPLE_DISTRIBUTION_P12_BASE64`, `APPLE_DISTRIBUTION_P12_PASSWORD`,
   `APPLE_PROFILE_BASE64`, `APP_STORE_CONNECT_KEY_BASE64`) with a provisioning
   profile for **`app.pourpaint.game`**.
4. Run `python3 scripts/apple-release-check.py` any time for the safety gates
   (bundle identity, portrait-only, no banned SDKs, no http:// URLs, AdMob
   test-ID reminder).
5. Trigger the workflow via **workflow_dispatch on main** → signs, validates
   with Apple, optionally uploads to App Store Connect (never submits).
